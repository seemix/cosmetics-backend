# Залишки у відповідях сайту: що змінилося для фронтенду

Зміни комітів `7611942` (S2.7, В4), `19d0031` (FINDING-12), `69c7915` (FINDING-11), `fc4b451` (FINDING-9).
Кількість на складі сайт не отримує ніде, крім наближеного `available` у помилці 409 для авторизованих.

## 1. Нове поле `inStock: boolean` у товарах

Є в кожному товарі відповідей:

| Ендпоінт | Де товари |
|---|---|
| `GET /api/products/products-category/:slug` | `products[]` |
| `GET /api/products/products-brand/:slug` | `products[]` |
| `GET /api/products/products-search` | `products[]` |
| `GET /api/products/bestsellers` | `products[]` |
| `GET /api/products/:identifier` (id або slug) | сам товар |

Значення (`loadInStock`, `Products/services/productsByRelation.service.ts`):

- облік складу вимкнено (`accounting-settings.stockControlEnabled = false`) або не задано `defaultWebWarehouse`:
  завжди `true`;
- облік увімкнено: `true`, якщо залишок товару на складі сайту (`defaultWebWarehouse`) більший за 0, інакше `false`.

Градацій («мало», «більше 10») немає. Для них потрібне окреме поле й зміна рішення В4.

## 2. Поле `inventory` прибрано

`inventory` (лічильник ecommerce-плагіна) більше не віддається в жодному з ендпоінтів вище: з каталогу бренду
й категорії його прибрано в `19d0031`, в одному товарі, пошуку й бестселерах його не було й раніше.
Фронтенд, який читав `inventory`, має перейти на `inStock`.

## 3. `unavailable` не змінився

`unavailable` лишається ручним прапорцем із адмінки й від залишків не залежить. У каталозі бренду й категорії
товари з `unavailable: true` і далі йдуть у кінець списку. За `inStock` список не сортується й не фільтрується:
товар із `inStock: false` стоїть на своєму місці.

Рекомендація для відображення: «немає в наявності», якщо `unavailable === true` або `inStock === false`;
кнопку «у кошик» для таких товарів вимикати.

## 4. Нестача при створенні замовлення: `POST /api/orders/create` → 409

Замовлення сайту створюється в `pending` і склад не списує: залишок зменшується, лише коли менеджер його
відвантажує (В20). Резерву немає, тож `inStock` до відвантаження не змінюється.

Якщо на складі сайту менше, ніж замовлено, замовлення не створюється:

```json
{
  "success": false,
  "code": "INSUFFICIENT_STOCK",
  "message": "Some items are not available in the requested quantity",
  "items": [{ "product": "<id>", "requested": 12, "available": 10 }]
}
```

- `available` є лише для авторизованого користувача. Гість отримує тільки `product` і `requested`.
- `available` наближене: округлення вниз до кратного 5, але не менше 1, якщо товар ще є
  (3 → 1, 7 → 5, 23 → 20, 0 → 0). Не показувати його як точний залишок.
- `message` перекладено за `Accept-Language` (`en`, `ru`, `ro`). Орієнтуватися варто на `code`, а текст показувати свій.
- Склад і точний залишок у відповідь не потрапляють.

## 5. Чернетки товарів

Товари зі статусом `draft` більше не віддаються в публічних ендпоінтах (для гостя й покупця). Чернеткий товар
за id або slug дає 404 `Product not found`; у кошик і замовлення він не потрапляє.

## 6. Детальні залишки лише для адмінки

`GET /api/stock/product/:id` повертає залишки по складах лише admin і manager (manager без собівартості).
Сайт цей ендпоінт не викликає: гість і покупець отримують 401 / 403.
